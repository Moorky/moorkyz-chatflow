## Findings (severity ordered)

No **Critical** or **High** findings.

- **F-01 / Medium (release process) / Candidate superseded during audit.** Reproduction: `git log -1 dev` in the implementer repo now shows `16b61ec` (pushed 02:37:41, also on `origin/dev`/PR #2). Impact: the PR #2 head now points at untested code; none of this report's evidence covers it. Fix: tag exactly `cf302f2`, or rerun the full gate (fresh clone, `npm ci`, `test:all`, installed-ZIP smoke) on `16b61ec` or the final SHA and wait for its CI to succeed. Verification: on review, the diff is behavior-preserving. `renderInventory(indexedMessages?)` reuses the worker-provided `result.indexedMessages`, which `SearchIndex` computes under the same branch policy. It still needs to be run.
- **F-02 / Medium (truthfulness, T24) / Compatibility with a real export is unverified, and the user-facing docs do not say so.** Reproduction: README "What exists today"/Quickstart and the CHANGELOG 1.0.0 entry say "Import an official export ZIP…" without saying that only synthetic official-shaped fixtures were tested. The NOT RUN appears only in `.audits/2026-11-08-focused-mvp.md` (CF-33) and the PR body. Impact: a stable "1.0.0" release could imply it is proven against real exports, while OpenAI export schemas can drift. Fix: either run `npm run test:real` privately with an owner export, or add one sentence to README/CHANGELOG/release notes, e.g.: "Validated with synthetic official-export-shaped data; not yet verified against a current real export." Verification: doc diff review.
- **F-03 / Medium (G4) / Manual screen-reader spot check not performed.** The project's own audit records this (CF-22), and I did not perform it either. Impact: assistive-technology usability of dialogs and live regions is unconfirmed beyond axe. Fix: a 10–15 minute Narrator or NVDA pass over import → search → viewer → export → clear, recorded in `.audits/`, or explicit written owner acceptance of the gap.
- **F-04 / Medium (G0, default branch) / GitHub `master` still has the EINTEGRITY lockfile.** Reproduction: `git show f5cfac8:package-lock.json` contains `"node_modules/yocto-queue": {"version": "1.0.0", … yocto-queue-1.0.0.tgz, integrity sha512-rVksv…` (that is the 0.1.0 hash). Impact: anyone cloning the default branch gets an `npm ci` failure, which breaks the README quickstart. The repository is private, so there is no exposure yet. Fix: fast-forward `master` to the verified SHA through PR #2 before any visibility change or tag (`f5cfac8` is an ancestor of `cf302f2`). Verification: `npm ci` in a fresh clone of `master`.
- **F-05 / Medium (G5, artifact provenance) / The release ZIP hash depends on the working tree it was built in.** Reproduction: the implementer working copy has `NOTICE` checked out with CRLF (`git ls-files --eol NOTICE` → `i/lf w/crlf`, despite `* text=auto eol=lf`). Its `artifacts/moorkyz-chatflow-1.0.0.zip` (38,806 B, SHA-256 `74c0c34e…02b7`, built 02:37) differs from the clean-clone build (`cadce460…8718`, identical across 3 builds). The differences: NOTICE is 413 vs 403 bytes, and the JS bundle came from post-candidate source. Impact: if the working-copy ZIP is uploaded, its published SHA-256 cannot be reproduced from the tag, and it does not match the audited artifact. Fix: build the release asset only from a clean clone or CI at the tagged SHA. Optionally renormalize the working copy (`git rm --cached -r . && git reset --hard` or a fresh clone) and make `scripts/package.mjs` reject CRLF in LICENSE/NOTICE. Verification: recompute the SHA-256 from a clean clone.
- **F-06 / Low / README overstates release automation.** "Tagged GitHub releases attach this ZIP and its `.sha256` file." No release workflow exists (ci.yml only verifies), and no tags or releases exist. Fix: reword as a manual owner step or add a reviewed release workflow.
- **F-07 / Low / A stale tracked audit is linked from the README.** `.audits/2026-11-08-focused-mvp.md` still says "CF-03: product license … none added", "CF-35: remote CI has **not** run" and "NO-GO … until license, remote CI…". Commit `4059f12` (Apache-2.0) and CI runs 42434478144/42434483528 superseded those statements. Fix: add a dated addendum.
- **F-08 / Low / CSV column mislabel.** In the `conversations.csv` export, message rows put `message.contentKind` (`text`/`multimodal`/`unavailable`) in the column headed `coverage_warnings` (`src/exports/export.ts`, message row). No data is lost, but the column name misleads. Fix: add a `content_kind` column or populate warnings consistently.
- **F-09 / Low / Raw invalid-UTF-8 error.** Importing invalid UTF-8 JSON shows "Failed to execute 'decode' on 'TextDecoder': The encoded data was not valid." The message is accurate and safe, and the snapshot is preserved, but it does not tell the user what to do. Fix: wrap it in "The file is not valid UTF-8 JSON…".
- **F-10 / Info / UI excluded from coverage.** `vitest.config.ts` excludes `src/ui/**` (41 KB `main.ts`, which holds every `innerHTML` sink). I reviewed every `innerHTML` interpolation by hand. Each untrusted string goes through `escapeHtml`, except `formatTime(…)` values, which are ISO strings produced by `toISOString()` in `normalize.ts` and re-validated by round-trip in `storage/validate.ts`, plus numbers and constants. `href`s are limited to validated `https://chatgpt.com/c/<id>` URLs. Viewer message bodies use `textContent`. No injection was found.
- **F-11 / Info / Packager hardening.** `scripts/package.mjs` asserts the absence of `permissions`/`host_permissions` but not `content_scripts`, `externally_connectable` or `web_accessible_resources`. All are currently absent (I verified). Suggest extending the assertion.
- **F-12 / Info / Publication hygiene.** The commit metadata contains the owner's work email address, which becomes public with the repository. The implementer repo also has local-only `refs/agents/*` checkpoint refs. I scanned them, they contain no secrets, and they should not be pushed.
